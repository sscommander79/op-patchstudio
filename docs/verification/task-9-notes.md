## Additional source-level network-content finding (Astra, during Task8)
`src/utils/patreonPosts.ts` fetches optional donation posts through public CORS proxies, then removes only disallowed tag names while retaining all attributes on allowed `a`, `p`, `b`, etc. `DonatePage.tsx` renders the resulting excerpt with dangerouslySetInnerHTML (inspected line239). Consequently event attributes and unsafe anchor URLs on allowed tags are not removed by this regex. This is an actual remote-HTML trust-boundary defect, not a dependency advisory or a claim of observed exploitation. Fix under Task9 quality/security: prefer plain text React rendering for excerpts and separately validate navigable URLs; if formatted HTML is necessary, use a maintained sanitizer with explicit allowed markup/URL policy and current primary docs. Preserve upstream author/donation attribution and graceful offline behavior. Add a bounded malicious-response regression through the real parser/render path proving event attributes/unsafe URLs cannot become active markup; no external request or real script execution is needed.
