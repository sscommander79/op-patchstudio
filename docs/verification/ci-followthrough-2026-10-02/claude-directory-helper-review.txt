## Checked, no finding

- **No genuine import defect is masked.** The helper only accepts a `TimeoutError` if both the `input` and `change` events recorded exactly the expected names and folder paths. The dialog, both file names, Cancel, dialog-hidden and "0 of 24 loaded" assertions are unchanged in `file-entry-audit.spec.ts`. The only thing given up is Playwright's own confirmation that the event reached its listener, which says nothing about the app.
- **The recording happens before React clears the input.**
  - For file inputs, React's `onChange` runs on the native `change` event, through its listener at the root.
  - The helper's listeners sit on the element itself, so they fire first. The value reset at `DrumTool.tsx:440` and `MultisampleTool.tsx:406` can't empty the record first.
  - The `input` event fires before `change`, and a script setting `value=''` fires no event, so nothing overwrites the record.
- **Nothing leaks after a timeout.**
  - Playwright 1.63's leftover listener promise has a `.catch(()=>{})` attached (`coreBundle.js:20520`), so no unhandled rejection.
  - Its once-only `input` listener stays on the element until the page closes. The test makes no second folder selection, so it's harmless.
  - The helper removes its own listeners and frees its handle in `finally`.
- **The error filter is narrow.** `errors.TimeoutError` from `@playwright/test` is the same class the client throws, so other errors pass through. The "transport error" case checks this by identity.
- **The negative cases are valid.** A failed non-soft `expect` just throws (`expect.js:13322-13328`), so `rejects.toThrow` passes cleanly. The report will show a red step inside a passing test, which is expected.
- **The injected fault is limited to what was claimed.** The injected function on the chooser only changes whether `setFiles` completes. In "completed selection" and "wrong files" the real `setFiles` still runs, and "missing events" skips it.
- **No other folder uploads exist.** `file-entry-audit` has the suite's only `webkitdirectory` upload, so no other test still uses the unprotected path.

`★ Insight ─────────────────────────────────────`
- The helper works because the DOM delivers an event to listeners on the element itself before it bubbles up to React's single root listener. That ordering is the only reason the file list can be read before React's `onChange` sets `value=''`.
- The real bug is one missing `await` in Playwright: it starts registering its `input` listener and sends the files at the same moment. Chromium happens to make an extra round trip first, so its listener wins. Firefox and WebKit don't, which is why only they hang.
- With a fixed file list in CI, adding a spec to the repo doesn't make it run on every browser. Check the job list as well as the test directory.
