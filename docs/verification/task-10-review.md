## Findings

### R10-1 — P2: The production CI command runs tests that require the development source server

**Locations:** `.github/workflows/quality.yml:29` and `:45`; `playwright.config.ts:47`; `tests/e2e/recovery-integrity.spec.ts:16` and `:67`; other affected imports in `tests/e2e/export-workflow.spec.ts:103`, `:111`, `:148`, and `:230`. Public command claim: `README.md:86` and `:91`.

The workflow selects `PLAYWRIGHT_PRODUCTION=1`, which serves `dist` with preview. Several included tests dynamically import `/src/utils/*.ts` in the browser. Those are Vite development-server module URLs and are absent from the production build. Consequently clean CI reaches a deterministic harness failure before the asserted transaction/audio behavior is exercised. The passing development-server matrix and bespoke production/offline proofs do not make this configured production-matrix command valid.

**Independent reproducer:** `PLAYWRIGHT_PRODUCTION=1 npx playwright test tests/e2e/recovery-integrity.spec.ts --project=chromium --workers=1 --retries=0`. Result: **0 passed / 2 failed**. The two exact errors were `Failed to fetch dynamically imported module: http://127.0.0.1:5187/src/utils/defaultSettings.ts` and the corresponding `/src/utils/libraryUtils.ts`. Log: `/tmp/opstudio-task10-production-storage-review.log`. Both test bodies failed in under 100 ms; this is not a slow-storage or recording-timing failure. It proves the current local production command is broken, not that remote CI was executed or that application storage is corrupt.

**Required correction:** make the configured production tests consume only production-available interfaces. Browser-native IndexedDB adapters can inspect or seed actual UI-created data without importing application source. If direct source-module integration tests are retained separately, give them an explicitly named development-server target and run that target as well as genuine production workflows in CI. Preserve rollback, precision, settings-only/old-session recovery and real archive assertions; do not close the finding by silently skipping storage checks or exposing development source in the public build. Validate the repaired affected production cases and the final commands actually selected by CI, with README/ledger evidence matching those commands.

### R10-2 — P2: Recording and slicing can commit a project that no longer supports its own backup

**Locations:** `src/context/AppContext.tsx:988`–`:1002` (slice candidate and successful receipt), `src/utils/recordingApplication.ts:116`–`:119` and `:130`–`:133` (recording capacity/return), `src/context/AppContext.tsx:1009`–`:1018` (recording commit). Shared complete metadata gate: `src/utils/projectArchive.ts:278`; manifest byte check: `:46`.

These creative paths enforce audio/source/count/ZIP-overhead capacity, reserving 2 MiB for manifest data, but do not validate the **actual final manifest** before publishing the candidate. A previously accepted raw preset can already consume that 2 MiB. Adding even tiny audio adds sample descriptors, references and provenance, so the resulting actual JSON exceeds the limit despite having ample audio capacity. The UI reports success and retains a history entry; downloading its portable backup then fails.

**Bounded actual-source evidence, implementation-worker probe inspected by this reviewer:** accepted imported settings with a filler length of **2,095,959** produced a manifest of exactly **2,097,152 bytes** and an actual valid portable archive of **2,097,276 bytes**. Starting from that valid state, actual reducer `COMMIT_PREPARED_RECORDINGS` with an **8-frame mono** take returned `committed` and added one history entry. Both the zero-PCM metadata validator and actual archive exporter then threw **`Project manifest is too large`**. Actual `COMMIT_PREPARED_SLICES` with a **4-frame slice from an 8-frame source** had the same result. Undo restored a portable state in both cases. This is a successful-but-unbackable project, not an inferred large-audio allocation failure or irreversible loss of the prior state.

**Required correction:** validate the complete final candidate with the shared zero-PCM metadata validator at the atomic commit boundary, after all source retention, slice provenance and destination assignments are known, and before a success receipt/history edit is published. On rejection preserve current musical state and history, report the specific failure, and retain the recorder/import review or slice draft for adjustment. Keep existing audio/count/ZIP-overhead checks. Add exact-boundary accepted-before/rejected-after regressions for both modes, a valid growth-with-headroom success control, and actual export/reopen assertions for accepted candidates. Studio Seed already calls the shared validator on its final candidate at `src/utils/studioDemo.ts:164`; preserve that safeguard.

### R10-3 — P2: Multisample import validates before it derives crossfade provenance

**Locations:** `src/utils/audioImport.ts:71`–`:74`; published by `src/context/AppContext.tsx:1026`–`:1032`. Derivation: `src/utils/importedCrossfade.ts:111`–`:113`; archive reference rule: `src/utils/projectArchive.ts:210`.

The per-file multisample trial passes metadata admission, then `associateImportedCrossfades` changes the final array after all those validations. This defeats Task 7's shared reference validation whenever the new association has metadata the portable archive refuses. A normal-size preset suffices; no near-limit string is required for this finding.

**Actual-source trigger:** while no matching audio is loaded, accept a multisampler preset containing `regions: [{sample: "match.wav", framecount: 8, "loop.crossfade": 0.5}]`. Its uninterpreted raw JSON is valid and the pre-audio project passes metadata admission. Import an **8-frame `match.wav`** through actual `COMMIT_PREPARED_IMPORTS`. The probe observed `committed`, one history entry, and newly derived **`loopCrossfade.importedRaw: 0.5`**. Both final metadata validation and real backup export then failed **`Invalid imported crossfade value`** because the archive requires an integer provenance field. Undo restored portability.

This does not reopen the earlier explicit-settings-import trigger, which now validates after association; it is the later audio-add ordering seam. The same ordering also leaves post-association manifest growth unchecked, but this report does not claim an independently reproduced byte-overflow variant for multisample import.

**Required correction:** apply association before validating each candidate that will be admitted, or validate the fully associated final candidate atomically before its success is published. Preserve accepted uninterpreted raw settings without rounding, and either retain unsupported values only in that raw form or reject the audio addition safely under the established policy. Preserve partial-intake behavior and explicit destinations for valid assets. Tests must verify rejection retains current project/history and review assets, and that ordinary integer crossfade association still commits, exports and reopens. One final-candidate validator must guard both reference validity and final manifest bytes.

**Shared probe artifacts:** `/tmp/opstudio-task10-manifest-admission-probe.json` and `/tmp/opstudio-task10-manifest-admission-probe.log`. The diagnostic is **1/1 passing because it asserts the reproduced failures**; it is not a product acceptance pass.
