**Findings**
1. **Medium: Assistive activation can start a note without releasing it.**  
   `src/components/multisample/VirtualMidiKeyboard.tsx:522-526`, `src/components/multisample/MultisampleTool.tsx:298-357`, `src/hooks/useAudioPlayer.ts:689-871`  
   Reproduction: activate a loaded virtual key through a screen reader or synthetic accessibility click (`detail === 0`). The component calls async `onKeyClick` and immediately calls `onKeyRelease`. Playback does not register the note globally until after awaiting the audio context, so release finds nothing; the voice then starts without entering release. Looping samples can sustain indefinitely. Existing tests only use synchronous spies and miss this race.

2. **Medium: Window blur does not release pointer- or touch-started notes.**  
   `src/components/multisample/VirtualMidiKeyboard.tsx:73-92`, `src/components/multisample/VirtualMidiKeyboard.tsx:528-568`  
   Reproduction: mouse-down or touch-start a sustained loaded key, then switch windows/tabs before mouse-up/touch-end. `releaseHeldNotes` releases only physical-keyboard and focused-keyboard notes; `mousePressedKey` is merely cleared, touch ownership is not tracked, and there is no `touchcancel` handler. The missing release can leave the voice sounding. Unmount/deactivation are covered for physical and focused activation, but not pointer, touch, or MIDI-held notes.

3. **Medium: Pointer movement can release a note owned by another input.**  
   `src/components/multisample/VirtualMidiKeyboard.tsx:540-553`  
   Reproduction: hold a note using the computer keyboard or MIDI, then move the pointer into and out of the corresponding virtual key. `onMouseLeave` calls `onKeyRelease` for every assigned key without checking whether that key received the mouse-down, prematurely cutting the independently held voice.

4. **Low: F5 includes a reachable focus-trap defect, although cross-dialog conflict remains theoretical.**  
   `src/components/common/SessionRestorationModal.tsx:44-73`, `src/components/common/SessionRestorationModal.tsx:234-274`  
   Reproduction: open restoration, move focus outside the two buttons by clicking non-focusable content, or start Restore/Start new so both buttons become disabled, then press Tab. The hand-written trap only wraps when focus is exactly on the first or last button, allowing focus into the underlying application. Escape intentionally preserving recovery is tested and is not defective. Coexistence with an owned dialog was not found reachable during normal startup.
